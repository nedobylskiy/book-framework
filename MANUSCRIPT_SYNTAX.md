# Синтаксис рукописи Book Framework

Файлы глав остаются обычными `.txt`, но Book Framework поддерживает небольшой Markdown-подобный набор переносимой разметки, которая преобразуется в возможности конкретного выходного формата.

Эти правила предназначены и для авторов, и для редакторов, и для ИИ, работающих с книжным репозиторием. Фреймворк намеренно не пытается реализовать весь Markdown/CommonMark: поддерживаются только конструкции, полезные для книг и технических текстов.

## Разрыв сцены

Отдельная строка из трёх дефисов означает усиленный вертикальный разрыв внутри главы:

```text
Первый эпизод закончился.

---

Прошло несколько часов.
```

При сборке:

- TXT: вставляются две пустые строки;
- FB2: вставляются два элемента `<empty-line/>`.

`---` должен находиться на отдельной строке. Это не горизонтальная линия и не часть текста книги.

## Внутренние заголовки

Название самой главы задаётся в `book.config.json`, поэтому `# Заголовок` внутри файла главы не используется. Для подразделов поддерживаются Markdown-подобные уровни от `##` до `######`:

```text
## Почему это важно

Текст раздела.

### Практический пример

Ещё текст.
```

При сборке:

- TXT: символы `##`–`######` снимаются, остаётся текст заголовка;
- FB2: внутренний заголовок создаётся как `<subtitle>`.

Уровень заголовка сохраняется в исходнике как структурная подсказка автору, редактору и ИИ. Текущая FB2-сборка намеренно не строит из уровней вложенное дерево `<section>` и выводит их единообразно как подзаголовки.

## Курсив и жирный текст

Используется привычный Markdown-синтаксис:

```text
Это *курсив*, а это **жирный текст**.
```

При сборке:

- TXT: маркеры `*` и `**` удаляются, остаётся обычный текст;
- FB2: `*текст*` превращается в `<emphasis>`, а `**текст**` — в `<strong>`.

Разметку рекомендуется использовать внутри одного абзаца и не растягивать через переносы строк.

## Inline code

Для коротких имён команд, параметров, переменных, файлов и фрагментов кода используются одиночные backticks:

```text
Команда `book build` читает `book.config.json`.
```

При сборке:

- TXT: backticks удаляются, содержимое остаётся без изменений;
- FB2: содержимое помещается в штатный элемент `<code>`.

Разметка внутри inline code не обрабатывается. Например, `` `**value**` `` остаётся буквальным `**value**`, а не жирным текстом.

## Блоки кода

Многострочный код оформляется fenced-блоком из трёх backticks:

````text
```js
const result = buildBook(config);
console.log(result);
```
````

После открывающих backticks можно указывать короткий идентификатор языка (`js`, `ts`, `json`, `bash`, `python` и т. п.). Сейчас он используется как метаданные исходника и не влияет на FB2/TXT-рендеринг.

При сборке:

- TXT: строки с тройными backticks удаляются, сам код и его отступы сохраняются;
- FB2: каждая непустая строка становится `<p><code>...</code></p>`, пустая строка — `<empty-line/>`.

Внутри fenced-блока никакая книжная разметка не обрабатывается: `---`, `##`, `![...]`, `[^note]`, `*...*` и другие конструкции считаются обычным кодом.

Блок обязательно должен быть закрыт. `book validate` и `book build` завершаются ошибкой при незакрытом fenced-блоке.

## Ссылки

Используется Markdown-совместимый синтаксис:

```text
Подробнее можно прочитать на [сайте проекта](https://example.com).
```

При сборке:

- TXT: `сайте проекта (https://example.com)`;
- FB2: создаётся кликабельный `<a l:href="https://example.com">сайте проекта</a>`.

Поддерживаются `http://` и `https://`.

Если текст ссылки совпадает с URL:

```text
[https://example.com](https://example.com)
```

в TXT URL не дублируется.

## Изображения

Изображение вставляется Markdown-совместимой конструкцией на отдельной строке:

```text
![Архитектура системы](assets/architecture.png)
```

Путь рекомендуется указывать относительно корня репозитория книги. Для FB2 поддерживаются локальные `.png`, `.jpg` и `.jpeg`.

### TXT

Без дополнительных настроек в текст попадёт репозиторный путь:

```text
Архитектура системы: assets/architecture.png
```

Если в `book.config.json` указан CDN:

```json
{
  "assets": {
    "baseUrl": "https://cdn.example.com/books/my-book"
  }
}
```

то результат будет:

```text
Архитектура системы: https://cdn.example.com/books/my-book/assets/architecture.png
```

Таким образом исходник не зависит от CDN: в главе всегда остаётся локальный путь, а публичный адрес задаётся на уровне проекта.

Для TXT допустим и прямой URL в конструкции изображения. В этом случае он выводится без изменений.

### FB2

Локальный файл читается из репозитория, кодируется в base64 и встраивается внутрь FB2 как `<binary>`. В месте изображения создаётся `<image l:href="#..."/>`.

FB2-сборка намеренно не скачивает удалённые изображения по HTTP/HTTPS. Это сохраняет сборку воспроизводимой и независимой от сети. Для FB2 используйте локальный файл в репозитории.

При сборке отдельных глав (`book build-chapters`) в каждый FB2 попадают только изображения, реально используемые в этой главе, плюс обложка книги, если она настроена.

## Сноски

Ссылка на сноску ставится в тексте так:

```text
Это важный термин[^term].
```

Определение сноски можно разместить в той же или другой главе книги отдельной строкой:

```text
[^term]: Пояснение важного термина.
```

Технический идентификатор (`term`) в готовую книгу не попадает. Нумерация назначается автоматически по порядку первого появления ссылок в книге.

Можно использовать любые короткие понятные идентификаторы:

```text
[^1]
[^source]
[^tripilon]
```

Рекомендуется использовать смысловые идентификаторы, потому что они устойчивее к добавлению новых сносок выше по тексту.

### TXT

В основном тексте ссылки превращаются в верхние цифры:

```text
Это важный термин¹.
```

Для номеров больше 9 используются последовательности верхних цифр: `¹⁰`, `¹¹`, `¹²` и т. д.

Все сноски собираются один раз в конце файла после разделителя:

```text
______

¹ Пояснение важного термина.
² Вторая сноска.
```

### FB2

В основном тексте создаётся стандартная FB2-ссылка типа `note`:

```xml
<a l:href="#note-1" type="note">1</a>
```

Сами примечания помещаются в отдельный блок:

```xml
<body name="notes">
  <section id="note-1">
    <title><p>1</p></title>
    <p>Пояснение важного термина.</p>
  </section>
</body>
```

Читалки с поддержкой FB2 могут переходить от номера к сноске и отображать её как примечание.

Ссылки, inline code, курсив и жирный текст внутри текста сноски также преобразуются в соответствующий выходной формат.

## Правила сносок

- Одно определение может использоваться несколько раз.
- Идентификатор определяется только один раз во всей книге.
- Каждая используемая сноска обязана иметь определение.
- Каждое определение должно хотя бы один раз использоваться.
- Нумерация сквозная по всей книге.
- Строки `[^id]: текст` не попадают в основной текст главы.
- Конструкции, похожие на сноски внутри fenced code block, игнорируются парсером.

Ошибки с определениями проверяются при `book build` и `book validate`.

Исходник:

````text
## Сборка проекта

Команда `book build` читает **конфигурацию книги** из `book.config.json`[^config].

```json
{
  "buildSource": "edited"
}
```

![Схема сборки](assets/build-flow.png)

Подробнее см. в [документации](https://example.com/docs).

[^config]: Конфигурационный файл в корне книжного репозитория.
````

Один и тот же исходник таким образом остаётся читаемым в GitHub/IDE и корректно адаптируется как к простому TXT, так и к FB2.
