# Book Framework

Шаблон и спецификация репозитория для написания, редактуры, документирования и сборки одной книги или рассказа.

## Основной принцип

**Одна книга = один Git-репозиторий.**

`book-framework` служит эталонным шаблоном. Для новой книги создаётся отдельный репозиторий с такой же структурой. Благодаря этому у каждой книги собственная история Git, issues, доступы, документация и публикационные артефакты.

Авторский текст никогда не перезаписывается редактурой: исходные главы находятся в `manuscript/chapters/`, редакторская версия — в `manuscript/edited/`.

## Структура книжного репозитория

```text
my-book/
├── README.md
├── book.config.json
├── manuscript/
│   ├── chapters/
│   │   ├── 01-prologue.txt
│   │   ├── 02-first-chapter.txt
│   │   └── ...
│   └── edited/
│       ├── EDITING_RULES.md
│       ├── 01-prologue.txt
│       ├── 02-first-chapter.txt
│       └── ...
├── docs/
│   ├── characters.md
│   ├── world.md
│   ├── organizations.md
│   ├── locations.md
│   ├── technology.md
│   ├── plot.md
│   ├── timeline.md
│   └── continuity.md
├── scripts/
│   ├── build.mjs
│   └── lib.mjs
├── dist/
└── package.json
```

## Имена и порядок глав

Файл каждой главы **обязательно начинается с её порядкового номера**.

Формат:

```text
NN-slug.txt
```

Примеры:

```text
01-prologue.txt
02-robocafe.txt
03-chase.txt
10-old-cyborg.txt
```

Требования:

- номер начинается минимум с двух цифр: `01`, `02`, ...;
- после номера ставится `-`;
- далее используется короткий латинский slug;
- редакторская версия главы должна иметь то же имя файла, что и оригинал;
- порядок глав в `book.config.json` должен совпадать с номерами файлов;
- номера не могут дублироваться.

Сборщик проверяет это автоматически. Например, если первым элементом `chapters` указан `02-chapter.txt`, сборка завершится ошибкой, потому что на первой позиции ожидается файл, начинающийся с `01-`.

Нумерация в имени нужна не только сборщику: она обеспечивает естественную сортировку глав в GitHub, файловом менеджере, IDE и других инструментах.

## Жизненный цикл текста

1. Новая глава создаётся в `manuscript/chapters/` с именем вида `NN-slug.txt`.
2. Этот файл считается авторским оригиналом.
3. После редактуры версия главы помещается в `manuscript/edited/` с **тем же именем**.
4. Правила редактуры конкретного произведения фиксируются в `manuscript/edited/EDITING_RULES.md`.
5. Факты мира, персонажей, сюжета и хронологии поддерживаются в `docs/`.
6. Сборщик создаёт готовые файлы книги в `dist/`.

## Правила редактуры

`manuscript/edited/EDITING_RULES.md` — обязательный проектный файл. В него необходимо записывать правила, которые редактор или ИИ должен соблюдать для конкретного произведения:

- авторский голос;
- допустимую степень переписывания;
- оформление диалогов;
- правила юмора;
- терминологию и имена;
- POV и время повествования;
- темп;
- особенности мира;
- изменения, которые запрещено вносить;
- любые локальные редакторские договорённости.

Правила конкретной книги имеют приоритет над общими рекомендациями фреймворка.

## README каждой книги

В корневом `README.md` конкретной книги рекомендуется держать:

- название;
- текущий статус;
- аннотацию;
- краткое описание проекта;
- ссылки на рукопись и docs;
- команды сборки.

Аннотация также хранится в `book.config.json`, поскольку используется при генерации публикационных форматов.

## Формат book.config.json

```json
{
  "id": "my-book",
  "title": "Название книги",
  "annotation": "Короткая аннотация произведения.",
  "status": "draft",
  "author": {
    "firstName": "Имя",
    "lastName": "Фамилия"
  },
  "language": "ru",
  "buildSource": "edited",
  "outputBaseName": "my-book",
  "genres": ["prose"],
  "chapters": [
    {
      "title": "Пролог",
      "file": "01-prologue.txt"
    },
    {
      "title": "Первая глава",
      "file": "02-first-chapter.txt"
    }
  ]
}
```

### Поля

- `id` — стабильный идентификатор книги;
- `title` — название;
- `annotation` — аннотация;
- `status` — например `idea`, `draft`, `editing`, `finished`, `published`;
- `author` — автор;
- `language` — язык;
- `buildSource` — `original` или `edited`;
- `outputBaseName` — базовое имя файлов в `dist/`;
- `genres` — жанры или теги;
- `chapters` — явный список глав в порядке книги.

Хотя порядок задаётся массивом `chapters`, номера файлов обязаны ему соответствовать. Таким образом порядок хранится одновременно в человекочитаемом имени файла и явно в конфигурации, а сборщик проверяет их согласованность.

## Документация мира

`docs/` — внутренняя энциклопедия произведения.

Рекомендуемые документы:

- `characters.md` — персонажи, характеры, отношения и текущее состояние;
- `world.md` — устройство и правила мира;
- `organizations.md` — компании, государства и группировки;
- `locations.md` — места;
- `technology.md` — технологии, магия, устройства или другие системы;
- `plot.md` — структура сюжета и основные арки;
- `timeline.md` — хронология;
- `continuity.md` — факты канона, которые особенно важно не нарушать в следующих главах.

Набор документов можно расширять под конкретное произведение.

## Сборка

Требуется Node.js.

```sh
npm run build
```

Собирает все поддерживаемые форматы.

```sh
npm run build:txt
npm run build:fb2
```

Источник текста определяется `buildSource` в `book.config.json`:

- `original` → `manuscript/chapters/`;
- `edited` → `manuscript/edited/`.

Результат сохраняется в `dist/`.

## Создание новой книги

Создайте новый отдельный репозиторий на основе структуры `book-framework`, затем:

1. заполните `book.config.json`;
2. замените содержимое корневого `README.md` на описание конкретной книги;
3. заполните `manuscript/edited/EDITING_RULES.md`;
4. добавляйте главы в `manuscript/chapters/` с последовательными номерами;
5. поддерживайте `docs/` по мере развития мира и сюжета.

Сам `book-framework` не является каталогом книг и не должен содержать несколько произведений одновременно.
